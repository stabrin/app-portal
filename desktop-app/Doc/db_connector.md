# Описание модуля `db_connector.py`

`db_connector.py` — это центральный модуль, отвечающий за управление всеми подключениями к базам данных PostgreSQL в приложении. Он использует механизм **пулов соединений** для повышения производительности и надежности, а также реализует "умную" логику для подключения к базам данных клиентов.

## Основные концепции

### 1. Пул соединений (`Connection Pooling`)

Вместо того чтобы открывать новое соединение с базой данных для каждого запроса (что является медленной операцией), модуль создает и поддерживает "пул" готовых к использованию соединений.

- **Эффективность**: Приложение "занимает" соединение из пула, выполняет запрос и "возвращает" его обратно. Это значительно быстрее, чем каждый раз проходить полную процедуру аутентификации.
- **Надежность**: Пул автоматически управляет "протухшими" или оборванными соединениями, заменяя их новыми.
- **Реализация**: Используется `psycopg2.pool.ThreadedConnectionPool`, что делает его безопасным для использования в многопоточном приложении.

### 2. Два типа пулов

Модуль управляет двумя видами пулов:

- **`main_db_pool`**: Единый пул для подключения к **главной базе данных** (`tilda_db`), где хранятся данные о клиентах и пользователях-супервизорах.
- **`client_db_pools`**: Словарь, где для **каждой клиентской базы данных** создается свой собственный, отдельный пул соединений. Ключом в словаре служит ID клиента.

### 3. "Умное" подключение к БД клиента

При первом запросе к базе данных конкретного клиента, функция `get_client_pool` выполняет следующую логику:

1.  **Попытка №1 (Внешний адрес)**: Сначала модуль пытается подключиться, используя **внешний IP-адрес** и **SSL-сертификат** (`db_host`, `db_port`, `sslmode='verify-full'`). Это основной и самый безопасный способ подключения.
2.  **Попытка №2 (Внутренний адрес)**: Если первая попытка не удалась (например, из-за проблем с сетью или сертификатом), модуль делает вторую попытку, используя **внутренний (локальный) IP-адрес** без SSL (`local_server_address`, `local_server_port`, `sslmode='disable'`). Это обеспечивает отказоустойчивость, если приложение запущено в той же локальной сети, что и сервер БД.

Как только одно из подключений проходит успешно, его параметры сохраняются в пул для этого клиента и используются для всех последующих запросов.

## Публичные функции (API модуля)

Эти функции-контекстные менеджеры являются основным способом взаимодействия с базами данных из других частей приложения.

### `get_main_db_connection()`

- **Назначение**: Получить соединение с **главной базой данных** (`tilda_db`).
- **Использование**:
  ```python
  from .db_connector import get_main_db_connection

  with get_main_db_connection() as conn:
      with conn.cursor() as cur:
          cur.execute("SELECT * FROM clients;")
          clients = cur.fetchall()
  ```

### `get_client_db_connection(user_info)`

- **Назначение**: Получить соединение с **базой данных клиента**.
- **Параметры**:
  - `user_info` (dict): Словарь с информацией о текущем пользователе, обязательно содержащий ключ `client_db_config` с параметрами подключения.
- **Использование**:
  ```python
  from .db_connector import get_client_db_connection

  # user_info получается после успешной авторизации
  with get_client_db_connection(user_info) as conn:
      with conn.cursor() as cur:
          cur.execute("SELECT * FROM orders;")
          orders = cur.fetchall()
  ```

### `get_client_db_direct_connection(user_info)`

- **Назначение**: Получить **прямое, непуловое** соединение с БД клиента.
- **Когда использовать**: Только для специфических задач, которые могут долго блокировать соединение или требуют уникального сеанса, например, для **обновления схемы базы данных** (`setup_client_database.py`). В обычной работе его использовать не следует.

## Внутренние (служебные) функции

- **`initialize_main_db_pool()`**: Вызывается один раз для создания пула главной БД.
- **`get_client_pool(pool_key, db_config)`**: "Сердце" модуля. Создает или возвращает существующий пул для клиента, реализуя логику двойного подключения.
- **`_get_cert_path(ssl_cert_content)`**: Вспомогательная функция, которая сохраняет текстовое содержимое SSL-сертификата во временный файл и возвращает путь к нему. Это необходимо, так как `psycopg2` требует путь к файлу сертификата.
- **`_attempt_db_connection(...)`**: Контекстный менеджер-помощник, который пытается установить однократное соединение с заданными параметрами для проверки их работоспособности.
