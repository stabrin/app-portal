# Описание статусов в системе "ТильдаКод"

Этот документ описывает значения полей `status` и `api_status`, которые используются в различных таблицах базы данных для отслеживания жизненного цикла сущностей, таких как уведомления, заказы и задачи.

## 1. Статусы Уведомлений о поставках (`ap_supply_notifications`)

Поле `status` в этой таблице отражает состояние уведомления от клиента.

*   **`Проект`**
    *   **Описание:** Уведомление создано, но находится в стадии черновика. Основная информация заполнена, но детализация заказа еще может отсутствовать или быть неполной.
    *   **Следующий шаг:** Заполнение детализации и перевод в статус "Ожидание".

*   **`Ожидание`**
    *   **Описание:** Уведомление полностью сформировано, детализация заказа загружена. Оно готово к дальнейшей работе.
    *   **Следующий шаг:** Создание на его основе производственного заказа.

*   **`Заказ создан`**
    *   **Описание:** На основе этого уведомления был успешно создан заказ в таблице `orders`. Уведомление считается обработанным.
    *   **Следующий шаг:** Работа с созданным заказом.

## 2. Статусы Заказов (`orders`)

В таблице `orders` используются два поля для отслеживания состояния: `status` для внутреннего процесса и `api_status` для взаимодействия с внешним API "Честного Знака".

### Поле `status`

Это основной статус, определяющий, как обрабатывается заказ.

*   **`new`** (или `NULL`)
    *   **Описание:** Заказ только что создан.

*   **`dmkod`**
    *   **Описание:** Заказ, который обрабатывается через интеграцию с API "Честного Знака" (ДМ.Код). Этот статус указывает приложению, что для данного заказа нужно отображать вкладку "АПИ".

*   **`delta`**
    *   **Описание:** Заказ, предназначенный для обработки во внешнем ПО (например, "Дельта"). Статус устанавливается после выгрузки данных для этой системы.

*   **`completed`**
    *   **Описание:** Внутренняя обработка заказа завершена (например, коды загружены из файлов и агрегированы). Заказ готов к печати или дальнейшим действиям.

*   **`archived`**
    *   **Описание:** Заказ перемещен в архив. Это не значение в поле `status`, а флаг `is_archive = true` в таблице. Такие заказы не отображаются в основном списке "В работе".

### Поле `api_status`

Это поле отслеживает шаги взаимодействия с API "Честного Знака".

*   **`NULL`** (пусто)
    *   **Описание:** Начальное состояние. Никаких действий с API еще не производилось.

*   **`Запрос создан`**
    *   **Описание:** В API "Честного Знака" успешно создан заказ на эмиссию кодов маркировки.

*   **`Коды скачаны`**
    *   **Описание:** Коды маркировки были успешно запрошены, сгенерированы и загружены в локальную базу данных.

*   **`Сведения подготовлены`**
    *   **Описание:** Данные об использовании кодов (агрегации) подготовлены для формирования отчета о нанесении.

*   **`Отчет подготовлен`**
    *   **Описание:** Финальный статус. Отчет о нанесении кодов успешно сформирован и отправлен в "Честный Знак". Работа с заказом через API завершена.

## 3. Статусы Производственных Задач (`production_tasks`)

Поле `status` в таблице `production_tasks` отслеживает жизненный цикл производственного задания, выполняемого оператором.

*   **`new`**
    *   **Описание:** Задача создана администратором, но еще не взята в работу. На этом этапе настраиваются параметры задания.
*   **`in_progress`**
    *   **Описание:** Задача активна и выполняется операторами. При переходе в этот статус запускается процесс наполнения пула кодов DataMatrix для печати.
*   **`completed`**
    *   **Описание:** Выполнение задания завершено.
*   **`error`**
    *   **Описание:** В процессе выполнения задания произошла ошибка. Требуется вмешательство администратора.
