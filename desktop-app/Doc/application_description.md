# Описание функциональности приложения "ТильдаКод" (desktop-app)

## 1. Общее назначение

**"ТильдаКод"** — это настольное Windows-приложение, разработанное на PySide6 (Qt), которое служит клиентским интерфейсом для работы с экосистемой `app-portal`. Оно предоставляет сотрудникам (администраторам, супервизорам, операторам) инструменты для выполнения производственных задач, связанных с маркировкой товаров, печатью этикеток и управлением данными.

Приложение спроектировано для работы в двух режимах:
*   **Онлайн-режим:** Подключение к удаленному серверу через интернет с использованием SSL-шифрования.
*   **Локальный-режим:** Работа в локальной сети предприятия без SSL.

## 2. Входные данные (Input)

Приложение оперирует следующими основными типами входных данных:

*   **Данные для авторизации:**
    *   **Администратор/Супервизор:** Логин и пароль для аутентификации в центральной базе данных портала.
    *   **Оператор:** Уникальный штрихкод-пропуск, который сканируется для входа в рабочий режим.

*   **Конфигурационные данные:**
    *   **`.env` файл:** Содержит ключевые параметры для подключения к базам данных (хост, порт, имя, пользователь, пароль).
    *   **Данные из БД портала:** После успешной авторизации администратора/супервизора приложение получает полную конфигурацию для подключения к базе данных конкретного клиента.

*   **Пользовательские данные:**
    *   **Шаблоны этикеток (JSON):** Макета, созданные во встроенном редакторе, описывающие структуру и содержимое этикетки.
    *   **Данные для печати:** Динамическая информация для подстановки в этикетки (например, GTIN, серийный номер, код DataMatrix).
    *   **Сканируемые коды:** Коды товаров (EAN, GTIN), коды агрегации (SSCC) и коды маркировки (DataMatrix), получаемые со сканера.
    *   **Изображения:** Графические файлы (например, логотипы), загружаемые пользователем для использования в макетах этикеток.

## 3. Архитектура и Сервисный слой

Приложение построено на многослойной архитектуре для разделения ответственности между компонентами.

### Точки входа

Существует два основных сценария запуска:

1.  **`run.py` (для Администраторов и Супервизоров):**
    *   Настраивает окружение и пути для корректной работы библиотек.
    *   Инициализирует модуль авторизации (`auth_qt.py`), который отображает окно входа.
    *   После успешной аутентификации определяет роль пользователя и запускает соответствующий интерфейс (`AdminWindowQt` или `SupervisorWindowQt`).

2.  **`run_oper.py` (для Операторов):**
    *   Упрощенная точка входа, которая читает конфигурацию напрямую из `.env`.
    *   Сразу отображает окно для сканирования пропуска.
    *   После успешной идентификации запускает специализированный рабочий интерфейс оператора (`OperatorWorkWindow`).

### Сервисный слой (Business Logic)

Вся бизнес-логика инкапсулирована в отдельных классах-сервисах, что позволяет отделить ее от пользовательского интерфейса.

*   **`db_connector.py` (Сервис подключения к БД):**
    *   **Функциональность:** Управляет всеми подключениями к базам данных PostgreSQL. Использует пулы соединений (`ThreadedConnectionPool`) для повышения производительности.
    *   **Логика:** Реализует "умное" подключение к БД клиента: сначала пытается подключиться по внешнему адресу с SSL, а в случае неудачи — по внутреннему адресу без SSL. Это обеспечивает отказоустойчивость.
    *   **Методы:** Предоставляет контекстные менеджеры `get_main_db_connection()` и `get_client_db_connection(user_info)` для безопасного получения и возврата соединений в пул.

*   **`PrintingService.py` (Сервис печати):**
    *   **Функциональность:** Отвечает за генерацию изображений этикеток и их отправку на принтер.
    *   **Входные данные:** JSON-шаблон, словарь с данными для этикетки (`{'datamatrix': '...'}`).
    *   **Логика:** На основе шаблона и данных рисует на холсте (библиотека Pillow) тексты, штрихкоды (Code128, QR, DataMatrix) и изображения. Взаимодействует напрямую с Windows GDI API (`pywin32`) для отправки задания на печать без вызова системного диалога.
    *   **Выходные данные:** Изображение этикетки (`Image` object) или прямая отправка на печать.

*   **`TaskService.py` (Сервис управления заданиями):**
    *   **Функциональность:** Обрабатывает логику, связанную с выполнением производственных заданий оператором.
    *   **Логика:** Управляет жизненным циклом задания: получение конфигурации, проверка отсканированных кодов, блокировка кодов в БД для предотвращения дублирования, обновление статусов.

*   **`CatalogsService.py` (Сервис справочников):**
    *   **Функциональность:** Предоставляет методы для работы со справочниками (товары, сопоставления кодов и т.д.).
    *   **Логика:** Выполняет CRUD-операции (создание, чтение, обновление, удаление) над таблицами справочников в базе данных.

*   **`ApiService.py` (Сервис API):**
    *   **Функциональность:** Отвечает за взаимодействие с внешними API, например, с API "Честного знака". (Примечание: в режиме оператора этот сервис не используется).

### Слой представления (UI)

Интерфейс построен на компонентах `PySide6`.

*   **Редактор макетов (`LabelEditorDialog`):** Визуальный инструмент для создания и редактирования JSON-шаблонов этикеток. Позволяет перетаскивать объекты (текст, штрихкоды), настраивать их свойства и привязывать к источникам данных.
*   **Окна ролей (`AdminWindowQt`, `SupervisorWindowQt`, `OperatorWorkWindow`):** Специализированные интерфейсы, предоставляющие доступ к функциям в соответствии с правами пользователя. Например, администратор может управлять пользователями и заданиями, а оператор — только выполнять назначенное ему задание.

## 4. Выходные данные (Output)

Результатом работы приложения являются:

*   **Напечатанные этикетки:** Физические этикетки с текстовой и графической информацией, штрихкодами и кодами DataMatrix.
*   **Данные в базе данных:**
    *   Обновленные статусы кодов маркировки (например, "использован", "агрегирован").
    *   Созданные записи об агрегации (связь "товар -> короб", "короб -> паллета").
    *   Обновленные записи в справочниках.
    *   Сохраненные JSON-шаблоны этикеток и загруженные изображения.
*   **Лог-файлы (`.log`):** Текстовые файлы с записями о ключевых событиях, ошибках и действиях пользователя, что помогает в отладке и анализе работы.
