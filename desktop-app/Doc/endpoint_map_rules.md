# Правила описания эндпоинтов для АПИ-Тестера

**Файл**: `src/admin_ui_qt.py`
**Метод**: `_define_endpoint_map`

Этот документ описывает правила и структуру для добавления новых эндпоинтов в АПИ-тестер настольного приложения. Метод `_define_endpoint_map` создает "карту", которая связывает отображаемое в интерфейсе имя эндпоинта с его поведением и необходимыми параметрами.

## Общая структура

Карта представляет собой словарь, где каждый ключ — это строка, видимая пользователю в выпадающем списке, а значение — это словарь с правилами.

```python
self.endpoint_map = {
    'Название эндпоинта в UI': {
        # ... параметры и правила ...
    },
    'get_participants': {
        'requires_order': False
    }
}
```

## Ключевые параметры (правила)

Каждый эндпоинт описывается набором следующих ключей:

### `method_name` (опционально)

-   **Тип**: `str`
-   **Описание**: Имя метода в классе `ApiService`, который должен быть вызван. Этот параметр используется, если название в UI (ключ словаря) не совпадает с именем метода в коде.
-   **Пример**:
    ```python
    'Детали заказа': {
        'method_name': 'get_order_details',
        # ...
    }
    ```
-   **Если отсутствует**: Тестер предполагает, что ключ словаря (`'get_participants'`) и есть имя метода в `ApiService`.

### `requires_order` (обязательно)

-   **Тип**: `bool`
-   **Описание**:
    -   `True`: Указывает, что для вызова этого эндпоинта необходимо выбрать заказ. В интерфейсе появится выпадающий список "2. Выберите заказ".
    -   `False`: Эндпоинт не привязан к конкретному заказу (например, `get_participants`). Дополнительные поля выбора не отображаются.

### `is_cyclic` (опционально)

-   **Тип**: `bool`
-   **Описание**:
    -   `True`: Указывает, что эндпоинт должен вызываться для каждого элемента *внутри* заказа (например, для каждого "тиража"). В интерфейсе появится третий выпадающий список "3. Выберите элемент цикла".
    -   `False` или отсутствует: Эндпоинт вызывается один раз для всего заказа.

### `cycle_item_source` (обязательно, если `is_cyclic: True`)

-   **Тип**: `str`
-   **Описание**: Указывает, откуда брать элементы для цикличного вызова.
-   **Возможные значения**:
    -   `'printruns'`: Тестер вызовет `order_service.get_unique_printrun_ids()` и заполнит список ID тиражей.
    -   `'utilisation_uploads'`: Тестер вызовет `order_service.get_all_utilisation_upload_ids()` и заполнит список ID выгрузок.

### `payload_generator` (обязательно для эндпоинтов, требующих аргументы)

-   **Тип**: `lambda`-функция
-   **Описание**: Генерирует тело JSON-запроса (payload).
-   **Аргументы функции**: `lambda oid, item_id: ...`, где `oid` — это ID выбранного заказа, а `item_id` — ID выбранного элемента цикла (если эндпоинт цикличный).
-   **Результат**: Функция должна вернуть словарь, который будет преобразован в JSON и показан в поле "Аргументы".

### `is_direct_http_call`, `http_method`, `http_path` (специальные параметры)

-   **Описание**: Эта группа параметров позволяет АПИ-тестеру выполнять прямые HTTP-запросы, минуя `ApiService`. Это полезно для тестирования эндпоинтов, для которых еще не написан специальный метод в сервисе.
-   **Параметры**:
    -   `is_direct_http_call: True`: Включает этот режим.
    -   `http_method`: HTTP-метод, например, `'POST'`.
    -   `http_path`: Путь к эндпоинту относительно базового URL (например, `'utilisation/upload'`).

## Пример

Рассмотрим описание эндпоинта `'create_utilisation_report_for_printrun'`:

```python
'create_utilisation_report_for_printrun': {
    'requires_order': True,
    'is_cyclic': True,
    'cycle_item_source': 'printruns',
    'payload_generator': lambda oid, item_id: {'order_id': oid, 'printrun_id': item_id}
}
```

**Как это работает:**
1.  Пользователь выбирает `'create_utilisation_report_for_printrun'`.
2.  Тестер видит `'requires_order': True` и показывает список заказов.
3.  Пользователь выбирает заказ.
4.  Тестер видит `'is_cyclic': True` и `'cycle_item_source': 'printruns'`, запрашивает у `OrderService` список тиражей для этого заказа и показывает их в третьем выпадающем списке.
5.  Пользователь выбирает тираж.
6.  Вызывается `payload_generator`, который формирует JSON: `{"order_id": 123, "printrun_id": 456}`.
7.  Этот JSON отображается в поле "Аргументы", и пользователь может нажать "Отправить запрос".

## Дополнительные примеры

### Пример для `upload_utilisation_data`

Этот метод отправляет сведения об использовании кодов. Он требует сложной структуры в теле запроса, поэтому `payload_generator` используется для создания шаблона, который пользователь может отредактировать вручную.

```python
'Загрузка сведений об использовании': {
    'method_name': 'upload_utilisation_data',
    'requires_order': True, // Привязываем к заказу для контекста
    'is_cyclic': False,     // Эндпоинт принимает пачку данных, а не один элемент
    'payload_generator': lambda oid, item_id: {
        "comment": "Это пример. Замените на реальные данные для заказа " + str(oid),
        "codes": [
            {
                "code": "010460406000653221...",
                "status": "APPLIED",
                "attributes": {
                    "production_date": "2024-01-01"
                }
            }
        ]
    }
}
```

## Существующие методы в `ApiService`

Ниже приведен список основных низкоуровневых методов, доступных в `ApiService`, которые можно вызывать через АПИ-тестер.

### Методы без привязки к заказу

*   **`get_participants`**
    *   **Описание:** Получает список всех участников (клиентов), зарегистрированных в "ДМ.Код".
    *   **Аргументы:** Не требуются.

*   **`authenticate`**
    *   **Описание:** Выполняет принудительную аутентификацию в API, используя учетные данные из конфигурации.
    *   **Аргументы:** Не требуются.

*   **`refresh_token`**
    *   **Описание:** Обновляет токен доступа, используя существующий refresh-токен.
    *   **Аргументы:** Не требуются.

### Методы, требующие ID заказа

Эти методы требуют, чтобы в `payload_generator` был сформирован JSON с соответствующими ID.

*   **`create_order(payload: dict)`**
    *   **Описание:** Создает новый заказ в "ДМ.Код".
    *   **Аргументы (payload):** Словарь сложной структуры, который генерируется методом `order_service.get_order_for_api_creation(order_id)`.

*   **`get_order_details(api_order_id: int)`**
    *   **Описание:** Получает детали заказа из API.
    *   **Аргументы:** `{"order_id": <api_order_id>}` (где `api_order_id` - это ID заказа в системе "ДМ.Код").

*   **`get_suborders(api_order_id: int)`**
    *   **Описание:** Получает список подзаказов (запросов на коды) для заказа.
    *   **Аргументы:** `{"order_id": <api_order_id>}`.

*   **`create_suborder_request(payload: dict)`**
    *   **Описание:** Создает запрос на эмиссию кодов для существующего заказа.
    *   **Аргументы (payload):** `{"order_id": <api_order_id>}`.

*   **`get_printruns(order_id: int)`**
    *   **Описание:** Получает список тиражей для заказа.
    *   **Аргументы:** `{"order_id": <api_order_id>}`.

*   **`create_printrun(payload: dict)`**
    *   **Описание:** Создает новый тираж для конкретного товара в заказе.
    *   **Аргументы (payload):** `{"order_product_id": <id_товара_в_заказе_api>, "qty": <количество>}`.

*   **`create_printrun_json(payload: dict)`**
    *   **Описание:** Запрашивает у API подготовку JSON-файла с кодами для конкретного тиража.
    *   **Аргументы (payload):** `{"printrun_id": <id_тиража>}`.

*   **`download_printrun_json(payload: dict)`**
    *   **Описание:** Скачивает готовый JSON-файл с кодами для тиража.
    *   **Аргументы (payload):** `{"printrun_id": <id_тиража>}`.

*   **`upload_utilisation_data(payload: dict)`**
    *   **Описание:** Отправляет сведения об использовании кодов (атрибуция, агрегация).
    *   **Аргументы (payload):** Словарь сложной структуры с кодами и их статусами.

*   **`get_utilisation_result(utilisation_upload_id: int)`**
    *   **Описание:** Получает результат обработки ранее отправленных сведений.
    *   **Аргументы:** `{"utilisation_upload_id": <id_загрузки>}`.

*   **`create_utilisation_report(payload: dict)`**
    *   **Описание:** Создает финальный отчет о нанесении кодов.
    *   **Аргументы (payload):** `{"printrun_id": <id_тиража>}`.

*   **`get_utilisation_subreports(api_order_id: int)`**
    *   **Описание:** Получает детализированный статус по каждому отчету о нанесении.
    *   **Аргументы:** `{"order_id": <api_order_id>}`.
