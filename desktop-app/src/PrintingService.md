# Описание класса `PrintingService`

`PrintingService` — это статический класс-сервис, предназначенный для генерации изображений этикеток и их последующей печати. Он не требует создания экземпляра и предоставляет набор утилит для работы с печатью.

## Основные зависимости

- **Pillow (PIL)**: Для создания и обработки изображений.
- **qrcode**: Для генерации QR-кодов.
- **pylibdmtx**: Для генерации кодов DataMatrix.
- **python-barcode**: Для генерации линейных штрихкодов (Code128).
- **pywin32**: Для прямого взаимодействия с API печати Windows.
- **psycopg2**: Для подключения к базе данных PostgreSQL.

## Публичные методы

Эти методы предназначены для вызова из других частей приложения.

### `generate_label_image(template_json, data, user_info, text_cache, static_layers_cache)`

Основной метод, который генерирует одно изображение этикетки.

- **Назначение**: Создает изображение на основе JSON-шаблона и переданных данных.
- **Параметры**:
  - `template_json` (dict): JSON-объект, описывающий макет этикетки (размеры, объекты, их координаты и свойства).
  - `data` (dict): Словарь с динамическими данными для подстановки в шаблон (например, `{'datamatrix': '...', 'gtin': '...'}`).
  - `user_info` (dict): Информация о пользователе для подключения к БД.
  - `text_cache` (dict, опционально): Кэш для ускорения рендеринга текста.
  - `static_layers_cache` (dict, опционально): Кэш для ускорения рендеринга статичных объектов.
- **Возвращает**: Объект `Image` из библиотеки Pillow в 1-битном (черно-белом) формате или `None` в случае ошибки.
- **Логика работы**:
  1. Создает пустой холст (`Image`) заданного в шаблоне размера.
  2. Последовательно обходит все объекты в `template_json['objects']`.
  3. Для каждого объекта определяет его тип (`text`, `barcode`, `image`, `text_with_image`).
  4. Получает данные для объекта из словаря `data` или, если их там нет, из базы данных клиента.
  5. В зависимости от типа, рисует на холсте текст, штрихкод или изображение.
  6. Применяет механизмы кэширования для ускорения повторной генерации одинаковых элементов.
  7. Возвращает готовое изображение.

### `print_label_direct(printer_name, paper_name, template_json, data, user_info, pregenerated_image)`

Отправляет одну этикетку на печать напрямую на принтер.

- **Назначение**: Печать одного изображения без вызова стандартного диалога печати Windows.
- **Параметры**:
  - `printer_name` (str): Системное имя принтера.
  - `paper_name` (str): Имя формата бумаги (например, `Tilda_100x50`), настроенного в системе.
  - `template_json` (dict): JSON-шаблон (используется, если изображение не было сгенерировано заранее).
  - `data` (dict): Данные для генерации (используются, если изображение не было сгенерировано заранее).
  - `user_info` (dict): Информация для подключения к БД.
  - `pregenerated_image` (Image, опционально): Уже сгенерированное изображение для печати.
- **Логика работы**:
  1. Если изображение не передано, генерирует его с помощью `generate_label_image`.
  2. Устанавливает соединение с принтером через `win32print`.
  3. Устанавливает заданный `paper_name` в настройках принтера.
  4. Масштабирует изображение, если оно не помещается на физический размер бумаги.
  5. Отправляет изображение на печать с помощью Windows GDI.

### `print_generated_images(printer_name, paper_name, images, user_info)`

Пакетная печать уже сгенерированных изображений.

- **Назначение**: Напечатать список готовых изображений.
- **Параметры**:
  - `printer_name` (str): Имя принтера.
  - `paper_name` (str): Имя формата бумаги.
  - `images` (list): Список объектов `Image` из Pillow.
  - `user_info` (dict): Информация о пользователе.
- **Логика работы**:
  1. Итерирует по списку `images`.
  2. Для каждого изображения вызывает `print_label_direct`, передавая его как `pregenerated_image`.

### `print_labels_for_items(printer_name, paper_name, template_json, items_data, user_info)`

Высокоуровневый метод для печати этикеток для списка элементов данных.

- **Назначение**: Сгенерировать и напечатать этикетки для целой пачки данных.
- **Параметры**:
  - `printer_name`, `paper_name`, `template_json`, `user_info`: Аналогично другим методам.
  - `items_data` (list): Список словарей, где каждый словарь — это данные для одной этикетки.
- **Логика работы**:
  1. Создает пустой список для изображений.
  2. В цикле для каждого элемента из `items_data` вызывает `generate_label_image` и добавляет результат в список.
  3. Вызывает `print_generated_images` для печати всего списка сгенерированных изображений.

## Внутренние (служебные) методы

Эти методы начинаются с `_` и используются внутри класса для вспомогательных операций.

### `_ensure_images_table_exists(conn)`

Проверяет наличие таблицы `ap_images` в БД клиента и создает ее, если она отсутствует. Это обеспечивает отказоустойчивость при работе с изображениями.

### `_get_client_db_connection(user_info)`

Создает и возвращает прямое подключение к базе данных клиента на основе `user_info`.

### `_fetch_data_from_db(user_info, data_source)`

Получает одно значение из БД клиента. `data_source` задается в формате `"имя_таблицы.имя_поля"`.

### `_get_multiline_fitting_font(draw, text, font_name, max_width, max_height)`

Подбирает оптимальный размер шрифта и автоматически переносит текст по словам, чтобы он гарантированно поместился в заданный прямоугольник (`max_width`, `max_height`).

### `_get_fitting_font(text, font_name, max_width, max_height)`

Подбирает максимальный размер шрифта для **однострочного** текста, чтобы он поместился в заданную ширину.

### `_get_sscc_human_readable(sscc)`

Форматирует 18- или 20-значный код SSCC в человекочитаемый формат с пробелами, например: `(00) 0 4604060 006532 5`.
